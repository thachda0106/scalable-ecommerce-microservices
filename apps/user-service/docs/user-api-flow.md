# User API Request Flow

The `user-service` handles incoming HTTP requests through a structured flow that enforces security, validation, and architectural boundaries.

## Detailed Flow

1. **Client Request**: An external client (web app, mobile app, or API gateway) sends an HTTP request (e.g., `POST /users/123/profile`).
2. **Routing & Controller**: The NestJS framework routes the request to the appropriate method in the `UserController`.
3. **DTO & Validation**: 
   - The payload is mapped onto a Data Transfer Object (DTO).
   - Validation pipes process the DTO (e.g., using `class-validator`) to ensure data integrity (e.g., checking email format, string lengths) before it reaches the business logic.
4. **Command/Query Dispatch**:
   - The Controller instantiates a specific Command (for mutations) or Query (for reads) using the validated data.
   - It dispatches this Command/Query to the corresponding Application Handler.
5. **Application Handler Execution**:
   - The Handler retrieves necessary Domain entities using the Infrastructure Repository (via the Domain Port).
   - **For Mutations**: The Handler invokes methods on the `User` aggregate root to enforce business rules and orchestrate state changes.
6. **Persistence & Event Publishing** (Mutations only):
   - The modified aggregate is saved back to the database via the Repository.
   - Any Domain Events generated by the aggregate are collected.
   - The Application Handler uses the Event Publisher port to dispatch these events to the messaging broker (e.g., Kafka) or Outbox table.
7. **Response**: 
   - The Handler returns the result to the Controller.
   - The Controller formats the standard HTTP response and returns it to the Client.
